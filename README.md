# 网页图库选图器 · ComfyUI-Shanggu-WebGallery

> 在 ComfyUI 节点里输入任意图片网址、网页或 JSON API，直接浏览缩略图；**点一下就等于「加载图像」**。开关拨到「单图」就运行 1 次工作流，拨到「多图」就按点选顺序让后面的图生图工作流**每张图各完整跑 1 次**，不需要任何额外循环节点。

一个给 ComfyUI 用的「网页找图 → 选图 → 喂给图生图」入口节点。适合从图站、素材页、模型展示页批量挑参考图，再把挑中的图接进 img2img / 反推提示词 / 风格迁移等工作流，不用来回手动下载、拖进 `input` 目录、再改 LoadImage 节点。

---

## 它解决什么问题

- **不用离开 ComfyUI 找图**：网址填进节点，缩略图网格直接画在节点面板里，向下滚动自动续加载。
- **点选即加载**：被点中的原图由后端下载到 ComfyUI 的 `input/` 目录并做本地缓存，节点输出标准 `IMAGE` / `MASK`，等价于内置「加载图像」节点，可以直接接给 VAE 编码、img2img、IP-Adapter 等。
- **一个开关决定一切**：只有「单图 / 多图」这一个开关。单图「点哪个换哪个」，运行 1 次；多图累加多选并按编号顺序，每张图各运行 1 次。
- **真正的循环执行**：多图模式下一次运行被拆成 N 个独立 prompt，每张图各跑一遍完整下游工作流。
- **顺手拿到页面信息**：`info_json` 输出原图网址、文件名、尺寸以及页面上抓到的 prompt 等字段，配套的「图库信息提取」节点可以把其中某个字段拆成文本，接给 CLIP 文本编码。

---

## 运行规则（重要）

ComfyUI 的一次运行就是一张**静态 DAG**：节点只能往前执行，没有任何节点能"回头"让下游再跑一次。所以「选 N 张图就跑 N 次」唯一稳妥的办法，是提交 N 个独立 prompt。

| 开关 | 点选行为 | 点一次运行 | 每次 prompt 里的图 | 节点输出 |
| --- | --- | --- | --- | --- |
| **单图** | 点哪个换哪个，永远只保留最后点的 1 张（再点一次取消） | **1 次** | 1 张 | `[1, H, W, C]` |
| **多图** | 累加多选，缩略图上显示选中顺序编号 | **N 次**（N = 选中张数） | 1 张 | `[1, H, W, C]` |

> 早期的版本还有「逐张 N 次 / 批量 1 次」两个执行按钮，现在已经**完全移除**。「批量一次」把 N 张打包成一个 `[N,H,W,C]` 的 IMAGE 张量，工作流其实只跑 1 次，既要求下游全部支持 batch、又容易撑爆显存，和「每个图片执行一遍工作流」自相矛盾；而它和「逐张」并列还会让同一个意图出现两种入口。现在执行次数只由「单图 / 多图」决定，不再有第二个开关。

实现细节：扩展 hook 的是 `app.queuePrompt`，只在「多图 + 选中 2 张以上」时介入；每轮临时把 `selected_files` 改成单张，再串行调用 ComfyUI 原生的 `queuePrompt(…, 1, …)`。每一轮都走完整的 `graphToPrompt` → `/prompt` → job 记录 → `processingQueue` 复位流程，因此队列面板、进度、错误提示都与手动点 N 次运行一致，不会卡住。单图模式完全不拦截，就是普普通通的一次运行。

**运行提交成功后会自动清空已选图片**（`selected_files` 写回 `[]`、缩略图上的编号和选中框全部消失），不用一张张点掉；图库网格仍保留，可以直接接着点下一批。只有提交成功才清空，运行报错时选区保持不变，方便重试。手动「清空选择」按钮也还在。

常见的「文件夹批量导入」型工作流，本质大多是 `Load Image Batch` 输出 IMAGE 批次、一次跑完；少数是用外部脚本逐张提交 prompt。本节点做的是后者，所以**不需要再挂循环节点 / 子图 / 批处理节点**，也不需要 API 脚本。

## 安装

1. 把整个文件夹放到 ComfyUI 的 `custom_nodes/` 下：
   ```
   ComfyUI/custom_nodes/ComfyUI-Shanggu-WebGallery/
   ```
2. 重启 ComfyUI（或浏览器 **Ctrl+F5** 强制刷新，扩展 JS 是动态扫描的）。
3. 双击画布搜索 **网页图库选图器**（`ShangguWebImageGallery`）、**图像扩图→Latent**（`ShangguImageExpandToLatent`）或 **图像重绘准备→Latent img2img**（`ShangguImagePrepForImg2Img`）。新增节点若没出现，重启一次 ComfyUI 即可。

无需 `pip install`：核心依赖 `aiohttp`、`PIL`、`numpy`、`torch` 都是 ComfyUI 自带的。

**可选依赖**（不用也能跑，只是能力增强）：

- `beautifulsoup4`：装了以后 HTML 标签解析更完整；没装会自动退回正则提取。
- `aiohttp-socks`：只有要用 `socks5://` 代理时才需要；HTTP 代理走 aiohttp 原生支持。

已在 **ComfyUI 0.45.0（前端 1.59.1）** 上开发验证。

## 快速上手

1. 节点面板的网址框里填地址，默认是 `https://civitai.red/api/v1/images?limit=20`。
2. 点 **搜索**，出现缩略图网格；**向下滚动**自动加载更多。滚到 1500 格时自动滚动会暂停（防止越滚越卡），状态栏会提示，此时点面板底部的 **「加载更多(解除上限)」** 就解除限制、继续一页页往下加载；解除后按钮变成「加载更多(不限)」，滚动也不再受 1500 格约束。重新点 **搜索** 会恢复默认软上限。
3. 面板顶部选 **单图** 或 **多图**：单图点哪个换哪个，运行 1 次；多图可点选多张（再点一次取消），每张各运行 1 次。
4. 点缩略图选中，原图会自动下载到 `input/`。
5. 把 `images` 输出接到图生图工作流，点面板的 **▶ 运行** 或 ComfyUI 的 **运行** 都行。

面板三个标签页：

- **网址抓取**：常规用法。
- **粘贴源码**：把网页 HTML、接口返回的 JSON、或每行一个图片网址直接粘进来解析，适合站点需要登录或纯前端渲染抓不到的情况。
- **浏览器桥接**：复制书签脚本，在自己已登录的浏览器页面点一下复制全部图片网址，再粘回来。

插队运行（Queue Front）时会按选中顺序提交，出图顺序与点选顺序一致。

> 如果多图工作流曾出现「卡住」，通常是旧版把多张网页原图（常有 1500~3000px）一起塞进 1024 工作流，latent 暴涨、16GB 显存很容易挂起。现在多图一定拆成 N 次独立运行，且所有图统一缩放到 `target_width/height`；确实要保留原分辨率，把 `size_mode` 设为「不统一(需同尺寸)」。

## 节点与输出

### 网页图库选图器 `ShangguWebImageGallery`

| 输出 | 类型 | 说明 |
| --- | --- | --- |
| `images` | `IMAGE` | 当前这一张图的张量 `[1, H, W, C]`，等价于 LoadImage |
| `masks` | `MASK` | 对应掩码（无 alpha 时为全 0） |
| `count` | `INT` | 本次加载的图片数量（正常恒为 1） |
| `info_json` | `STRING` | 这张图的元信息 JSON：原图网址、文件名、尺寸、页面 prompt 等 |

主要输入：`site_url`、`selected_files`（由面板自动维护）、`select_mode`、`size_mode`、`target_width`、`target_height`。

- `select_mode` 是唯一的模式开关，为可选输入，旧工作流没有它也能正常加载（默认单图）。
- `multi_mode` 是早期「逐张 / 批量」留下的**隐藏占位参数**，值被完全忽略，保留它只是为了让老工作流的 `widgets_values` 顺序不错位；前端会把它隐藏，你不会在节点上看到它。
- 多图模式如果一个 prompt 里意外收到 2 张以上（说明前端扩展没加载或工作流里有第二个多图节点），节点会明确报错而不是悄悄退化成批次，按提示 **Ctrl+F5 强制刷新**即可。

### 图库信息提取 `ShangguGalleryInfo`

把 `info_json` 里指定字段（如 `prompt`、`url`）按索引拆成 `STRING`，方便直接接文本编码节点做「看图写提示词」。

### 图像扩图→Latent `ShangguImageExpandToLatent`

一个节点**代替「缩放图像 + VAE 编码」**，专门解决「竖屏原图要生成横屏图」的问题。老的缩放节点只有两条路：居中裁切（只剩中间一条、主体丢失）或直接拉伸（变形、两侧黑框），都出不了满屏的横屏图。本节点走标准 outpainting：

```
原图(可竖屏) → 自动去掉源图自带的黑边 → 可选裁切上下 → 等比缩放(不拉伸)
            → 高度贴合、左右扩图 → 扩展区写进 mask → VAE 编码成带 noise_mask 的 latent
            → KSampler 按文本只补扩展区，原图部分原样保留
```

> **关于黑边**：图库下载的图常被 pad 成 9:16，四周自带一圈纯黑/纯白边。这圈边如果留在"原图保留区"（mask=0），采样器根本不会重绘它，成图就会带着黑条。节点默认开启 **`trim=自动去黑边`**，在缩放前先把这种"整条边几乎全是极黑/极白"的 padding 裁掉；判定很严格（要求 99% 像素一致、灰阶、亮度 <18 或 >238），暗色/夜景照片不会被误裁。如遇特殊构图需保留，选 `不去黑边` 即可。

| 输出 | 类型 | 说明 |
| --- | --- | --- |
| `latent` | `LATENT` | 带 `noise_mask`：**直接接 KSampler 的 `latent_image`**，扩展区会被文本补全 |
| `expanded_image` | `IMAGE` | 扩好图后的画布（扩展区是底色），可接 PreviewImage 看构图 |
| `expand_mask` | `MASK` | 扩展区为白（要重绘）、原图区为黑（保留） |
| `info` | `STRING` | 原图尺寸、目标尺寸、裁切量、贴入位置、扩展像素数 |

主要输入：

| 输入 | 默认 | 作用 |
| --- | --- | --- |
| `image` / `vae` | — | 输入图（可来自图库节点或 LoadImage）与编码用的 VAE（要和采样模型匹配） |
| `aspect` | `16:9` | 目标比例：16:9 / 3:2 / 4:3 / 1:1 / 3:4 / 9:16 / 2:1 / 21:9 / 自定义 |
| `long_side` | 1024 | 目标长边像素；短边按比例算并对齐到 8 的倍数 |
| `vertical_crop` | 0.0 | **从原图上下各裁掉的比例**。`0`=整张保留、左右扩最多；`0.1~0.2`=轻微裁切、人像更宽；越大主体越突出。节点会自动限制上限，保证裁完仍"高度贴合、左右扩图"，不会出现上下留空或把图压扁 |
| `position` | 居中 | 原图贴在画布的位置（居中/偏左/偏右/偏上/偏下） |
| `fill` | 中性灰 | 扩展区底色，中性灰是 inpaint 标准、latent 编码最稳 |
| `mask_grow` | 8 | mask 向原图内侧膨胀几像素，让接缝更自然；0=不膨胀 |
| `trim` | 自动去黑边 | **自动裁掉源图自带的纯黑/纯白 padding 边**（黑边元凶）；特殊构图可选 `不去黑边` |

**几何规则（保证不出黑边）**：源图先去黑边，再按 `vertical_crop` 裁上下，然后**固定"高度贴合画布"**等比缩放（不拉伸）。竖图 9:16 扩 16:9 时，人像宽度占比随裁切变化：`crop=0` 约 32%、`0.1` 约 40%、`0.2` 约 53%、`0.3` 约 79%——**任何设置下上下都零留空**，只有左右是扩图区。

用法：把 `latent` 接 KSampler 的 `latent_image`，positive 写你想扩出来的内容（如「延续的画面、背景、天空」），**denoise 建议 0.9~1.0**（太低会补不满扩展区）。要更干净的接缝，可在前面接 `InpaintModelConditioning`。竖图扩横屏时选 `16:9` + `vertical_crop=0`（完整保留、左右补），或 `vertical_crop=0.1~0.2`（轻微裁上下、人像更充盈、少扩一点）——这就是你要的「裁切上下一小部分或不裁切，再不拉伸地左右扩图」。如果成图还有黑条，先看 `expanded_image` 输出：若那里就有黑条，说明是源图 padding，`trim` 没识别时可手动裁源图或选纯色更接近的填充。

> 本节点输出的是 latent，**不是** IMAGE，因此它放在 VAE 编码那一步的位置，用不到也请删掉原来的「缩放图像 / VAE Encode」，别重复接线。

### 图像重绘准备→Latent img2img `ShangguImagePrepForImg2Img`

给「**大致保持人物和风格、动作可变、尺寸达标就行**」的重绘需求用。它和上面的扩图节点是**两个完全不同的东西**，别混：

| | 图像扩图→Latent | 图像重绘准备→Latent（本节点） |
| --- | --- | --- |
| 目标 | 补出新区域，原图像素一动不动 | 整张重绘成新图，人物/风格大致保持 |
| mask | 带 `noise_mask`，只重绘灰边 | **不带 mask**，整图按 denoise 重绘 |
| denoise | 0.9~1.0（要补满灰边） | **MOSS 完整保留+模糊背景：0.35~0.45；cover：0.18~0.30；SDXL/Flux：0.4~0.6**（MOSS 超过 0.5 会被文字带跑，人物变场景） |
| 尺寸 | 高度贴合、左右补灰 | **默认整图完整保留（一个像素不裁）+ 左右边缘延展；可选铺满裁切** |

工作流只有一条链：

```
图库节点(或LoadImage) → 本节点(aspect / long_side) → KSampler(latent_image, MOSS denoise 0.22) → VAEDecode → SaveImage
```

- **`fit` 默认 `完整保留(内容不裁切,推荐)`**：整图等比缩放后完整可见，**一个像素都不裁**。9:16 竖图转 16:9 时，人物只占中间约 32% 宽，两侧空区由 `pad` 填充——这就是你要的"重绘但不缺内容"。
- **`pad` 默认 `模糊背景(推荐)`**：整图放大后强高斯模糊铺满画布，再把清晰原图贴回中间。左右是原图色彩的柔和模糊、没有直线条纹也没有硬边，模型在 denoise 0.35~0.45 下会把它续绘成真实背景，中间清晰人像作锚点。
  - `镜像填充`：左右镜像原图，纹理连续但可能出现对称重影；
  - `边缘延展(会拉伸)`：把最边缘一列像素横向拉满——**会产生直线拉伸条纹，模型低 denoise 下原样保留，不推荐**；
  - `中性灰/黑/白`：纯色填充，容易在交界处画出硬矩形。
- `裁切填满(无留白,会裁上下)`：等比放大铺满、按 `position` 裁掉多余部分，画布无空边但**会切掉原图上下内容**——竖图转横图时人物可能只剩中间一条，只在你明确要铺满且接受裁切时才用。
- `size_multiple` 默认 **16**——**MOSS-Image 要求边长是 16 的倍数**，直接用默认即可；SDXL / Flux / H3 用 8 或 16 都兼容。
- 输出 `latent` **不带 `noise_mask`**，所以 KSampler 的 denoise 直接控制整图重绘强度；`prepared_image` 可接 PreviewImage 先看裁切构图对不对。

**关于 MOSS**：MOSS-Image 本体是纯文生图，**原生不认参考图**（模板里的 `ref_image` 只喂给可选的 prompt enhancer，模型读不到图像内容）。所以要"看着原图重绘"就必须走本节点的 img2img 通道，让原图 latent 当构图+风格底子。MOSS 采样建议：**50 steps / CFG 3 / euler + sgm_uniform / shift 5（ModelSamplingAuraFlow multiplier 1）/ skip layer guidance layer 22**，VAE 用 `flux2-vae`。显存方面 int8 主模型约 5.4GB + Qwen3.5 文本编码器约 7.3GB，16GB 卡能跑但较紧。

#### 排查：人物图被画成别的场景（例如公交站台）

MOSS 是文生图模型，img2img 时**文字的牵引远强于 latent**。denoise 一高，起始 sigma 已经接近纯噪声，原图 latent 几乎不起作用，模型就照着提示词重画一个新场景。按这个顺序排查：

1. **`prepared_image` 接 PreviewImage**：先确认节点输出的图里人物完整。竖图 9:16 → 16:9 必须用 `fit=完整保留(内容不裁切,推荐)`（默认值），整图一个像素不裁；若误选了 `裁切填满`，只会保留中间约 31% 高度，人物会被切掉大半——这就是"内容缺失"的根因。
2. **denoise 用 0.35~0.45**（完整保留+模糊背景模式）：低于 0.35 模糊区续绘不出来、留有雾感；高于 0.5 人物会被文字带跑变成别的场景。用 cover 铺满整图重绘时才用 0.18~0.30。
3. **确认 KSampler 接的是本节点的 `latent`**，不是 `EmptyLatentImage`，也不是旧「扩图→Latent」的输出。
4. **提示词里明确写人物**：以 `同一人物，同样的服装和发型，` 开头再写场景；负面提示词加 `different person, no person, change character, bus stop, billboard`（把不想要的具体场景词也写进去）。
5. **VAE 必须是 `flux2-vae`**（或官方配套的小 VAE）；用错 VAE 会让 latent 编码失效，表现同样是"完全看不出原图"。
6. 仍不行就先跑通纯文生图基线（官方工作流、1024×1024、denoise 1），确认模型/采样器本身正常，再换回本节点。

> 想要更强的"人物长得像"、跨场景保持同一角色，可以另装社区方案 `MOSS-Image CharRef v2`（edit LoRA + ostris 的 edit 节点，参考图接 `image1`，提示词以 `Same character and art style as Picture 1.` 开头）。但那要额外下 LoRA 和节点，且对"动作可 free 调整"的需求来说，本节点 + 合适 denoise 通常已经够用。

## 加载内容（榜单 / 排序）

`civitai` 和 `aitag.win` 的默认接口都是「按热度/时间排的默认流」，所以不指定排序时每次看到的几乎是同一批图。网址框下方的 **「加载内容」** 下拉就是用来换榜单的：选好后点 **搜索**（或切换时自动重搜），后端会按选中的榜单重新构造接口地址，出完全不同的图。每个站点记住自己上次选的榜单，来回切换不丢。

| 站点 | 可选项 | 实际接口参数 |
| --- | --- | --- |
| civitai | 最新上传 / 周榜 / 月榜 / 年榜 / 总榜 / 最多点赞 / 最多评论 / 最多收藏 | `sort=Newest` 或 `sort=Most Reactions\|Most Comments\|Most Collected`，榜单再加 `period=Week\|Month\|Year\|AllTime` |
| aitag.win | 最新作品 / 本月榜 / 当月实时榜 / 上月榜 / 往期榜 | 最新=`/api/ai_works_search`；月榜=`/api/rank/monthly[/real]`，往期用 `period=YYYY-MM` / `month=older` |

> `civitai` 的「最新上传」是 `sort=Newest`（实测会返回全新的高 ID 图片）；「总榜」是 `sort=Most Reactions&period=AllTime`。`aitag.win` 站点本身**没有**周榜/日榜/年榜接口（实测 404），下拉里就只有它真实支持的月榜系列。`aitag.win` 固定 18+，对榜单同样生效。

## 固定快捷按钮

网址框下方只有一个 **`civitai`** 按钮（对应 `https://civitai.red/api/v1/images?limit=20`），点一下即填入并抓取。没有自定义网站列表、没有「⚙ 网站」设置面板，也不需要：其他站点直接在网址框粘贴即可，站点类型（civitai / aitag / 其他）由网址自动识别，只影响「加载内容」下拉里显示哪组榜单。

## 站点适配 / 图片来源

### civitai.red

`https://civitai.red/images` 网页版会返回 **Cloudflare 403**，纯 HTTP 抓不到图；但同站的 `https://civitai.red/api/v1/images?limit=20` 是 200 直出 JSON，带 `items[].url` 和 `metadata.nextPage` 游标分页。因此节点内置了**自动改写**：直接输入 `/images` 也会切到该 JSON 接口，照样出图。配合「加载内容」下拉会自动追加 `sort` / `period` 参数（见上表）。

### aitag.win（SPA 图库）

`https://aitag.win/` 是纯前端渲染的站点：首页 HTML 里只有一张 `og:image`，瀑布流全靠 JS 调 `/api/ai_works_search` 填充，所以通用提取器直接抓首页会「一张图都没有」。节点内置了专用适配：

| 你填的网址 | 「加载内容」选最新时 | 选月榜系列时 |
| --- | --- | --- |
| `https://aitag.win/` | `/api/ai_works_search?page=1&page_size=60&sort=new&show_r18=1…` | `/api/rank/monthly[/real]?…`（往期带 `period=YYYY-MM` 或 `month=older`） |
| `https://aitag.win/?q=初音` | 同上，并保留 `q` 搜索词 | 同上 |
| `https://aitag.win/i/152099137` | `/api/work/152099137`，只出这一个作品的所有图（不受榜单影响） | — |
| 直接填 `/api/ai_works_search?...` 或 `/api/rank/...` | 同步 `show_r18`；若榜单与地址路径不一致则按下拉重建路径，其余查询项保留 | |

列表接口只给作品信息，图片真地址在 `/api/work/{id}` 的 `images[]` 里（`image_type/author_id/file_name.webp`）。适配器会**并发拉取详情**拼出站点 CDN 的 webp 直链并缓存每个作品的全部图片，但检索页只交付封面；一页 60 个作品约 2~7 秒，按 `page` 自动翻页滚动续加载。CDN 和 Pixiv 原图都有防盗链，节点会自动带上正确的 Referer，无需手动填。

#### 检索页 = 封面，点开才出同系列

该站原本是「检索页看封面 → 点作品看同系列所有页图」的两层结构，节点完整复刻：

- 一页 60 个作品就只有 **60 张封面**，封面左上角标 `1/N 张`；**没点开的作品一张同系列图都不显示**，所以检索页密度和网站一致，能一直往下翻。
- 点某张封面：把它载入工作流（跟原来的点选一样），同时把该作品其余 `N-1` 张图**紧挨着插到这张封面后面**（子图左侧有橙色竖条）。再点封面就是普通的选中 / 取消，封面右下角 `× 收起` 可以收回，收起不影响已经选中的图。
- 同系列图片由后端 `/sg_gallery/expand` 按作品 id 提供：抓列表时已缓存，展开几乎瞬间完成；ComfyUI 重启后从工作流恢复的旧封面，也能现场重新请求详情，照样点得开。
- `https://aitag.win/i/152099137` 这种直接指定单个作品的网址，仍然一次列出该作品的全部图，不折叠。

> 旧版本把每个作品的所有图片一次性摊平，导致两页就撞满 400 格的 DOM 上限、往下滚不动，也看不到检索页本身。现在自动滚动的软上限是 1500 格（约 25 页），并加了「整页无新图时自动续拉」与连续空页保护；**手动点「加载更多」可以完全无视这个软上限**。后端分页没有条数上限，只有站点自己到底（连续 3 次空页）才会停。

#### 18+ 自动开启（无按钮）

面板已移除 18+ 勾选框：**只要输入的网址属于 `aitag.win`，后端就强制 `show_r18=1`**，抓该站的成人作品集（总量约 285 万，与全年龄内容完全不同、不重叠），滚动翻页与切换榜单都会一直沿用。其他站点忽略该参数；即使旧工作流里残留 `r18=false` 也不会影响 aitag。

该站的 `/api/sensitive_works_search` 敏感专用接口受地区/语言策略限制会返回 `sensitive_content_blocked`，所以节点走的是普通列表接口的 `show_r18` 参数；实测 18+ 作品的详情与 CDN 直链都不需要额外的访问码或登录。请遵守当地法律与站点条款，未成年人勿用。

> 这类「HTML 只是壳」的 SPA 站点，通用抓取器天然看不到图片。遇到其他同类站点，若它没有内置适配，请用「粘贴源码」或「浏览器桥接」标签页，或直接把该站的 JSON 接口地址填进网址框。

抓取器能识别的来源：

- `<img>` 的 `src` / `data-src` / `srcset`、`<a href>` 指向的图片、`og:image`、CSS 背景图；
- `<script type="application/json">` 以及页面内嵌 JSON 里的图片字段；
- JSON API 响应（递归查找 url 字段）；
- 纯文本里每行一个网址；
- 自定义正则（`url_regex`）强制提取。

默认会过滤 logo / icon / avatar / placeholder / favicon 之类的非内容图，可在高级设置里关闭。

## 附带修复：DOM 面板「只占节点一半宽」

`js/sg_domwidget_width_fix.js` 是一个独立的通用前端补丁。ComfyUI 新版前端把 DOM 面板画在独立 HTML 覆盖层上，覆盖层宽度按 widget 创建时缓存的节点默认宽度计算，节点后来被拉宽或从工作流恢复尺寸时不会同步，于是面板只占一半宽——**所有带 DOM 面板的第三方节点都可能偶发**。

补丁每 250ms 巡检，只修明显卡在默认宽度的面板，不会动刻意做窄的布局。本节点自身也内置了宽度同步逻辑。

- 手动执行一次：浏览器控制台输入 `sgFixDomWidth()`
- 关闭：`localStorage.setItem('sg_domwidth_fix', 'off')` 后刷新页面

## 后端接口

节点通过 ComfyUI 的 `PromptServer` 注册以下路由（ComfyUI 0.45 会同时挂到 `/xxx` 和 `/api/xxx`）：

| 路由 | 作用 |
| --- | --- |
| `GET /sg_gallery/health` | 健康检查 |
| `POST /sg_gallery/fetch` | 抓取一页（带会话去重、游标分页、自动改写、榜单排序） |

## 已知限制

- 纯浏览器渲染、且需要登录/有强反爬的站点，后端直接抓可能拿不到图；目前只为 `civitai.red` / `aitag.win` 写了专用适配，其他同类站点请用「粘贴源码」或「浏览器桥接」标签页，或把它的 JSON 接口地址直接填进网址框。
- 多图模式总耗时约为单张 × N，队列里会依次出现 N 个任务，属正常现象；一个工作流里请只放一个处于「多图」模式的选图器节点。
- 自动滚动到 1500 格会暂停；点「加载更多」解除上限后可继续，直到 20000 格的浏览器安全兜底值（正常浏览到不了）。后端只在站点连续 3 次返回空页时判定到底。写进工作流的条目最多保存 3000 条，超过部分重新搜索即可；ComfyUI 重启后后端内存中的分页游标会清空，需再点一次「搜索」重新续拉。
- 抓取与缩略图缓存写在节点目录下的 `.cache/`，已加入 `.gitignore`；缓存的是第三方站点图片，请勿随仓库再分发。
- 请遵守目标站点的服务条款与图片版权，本节点只提供技术能力。
