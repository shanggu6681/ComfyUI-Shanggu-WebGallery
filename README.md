# 网页图库选图器 · ComfyUI-Shanggu-WebGallery

> 在 ComfyUI 节点里输入任意图片网址、网页或 JSON API，直接浏览缩略图；**点一下就等于「加载图像」**。开关拨到「单图」就运行 1 次工作流，拨到「多图」就按点选顺序让后面的图生图工作流**每张图各完整跑 1 次**，不需要任何额外循环节点。

一个给 ComfyUI 用的「网页找图 → 选图 → 喂给图生图」入口节点。适合从图站、素材页、模型展示页批量挑参考图，再把挑中的图接进 img2img / 反推提示词 / 风格迁移等工作流，不用来回手动下载、拖进 `input` 目录、再改 LoadImage 节点。

---

## 它解决什么问题

- **不用离开 ComfyUI 找图**：网址填进节点，缩略图网格直接画在节点面板里，向下滚动自动续加载。
- **点选即加载**：被点中的原图由后端下载到 ComfyUI 的 `input/` 目录并做本地缓存，节点输出标准 `IMAGE` / `MASK`，等价于内置「加载图像」节点，可以直接接给 VAE 编码、img2img、IP-Adapter 等。
- **一个开关决定一切**：只有「单图 / 多图」这一个开关。单图「点哪个换哪个」，运行 1 次；多图累加多选并按编号顺序，每张图各运行 1 次。
- **真正的循环执行**：多图模式下一次运行被拆成 N 个独立 prompt，每张图各跑一遍完整下游工作流。
- **顺手拿到页面信息**：`info_json` 输出原图网址、文件名、尺寸以及页面上抓到的 prompt 等字段。

## 运行规则（重要）

ComfyUI 的一次运行就是一张**静态 DAG**：节点只能往前执行，没有任何节点能"回头"让下游再跑一次。所以「选 N 张图就跑 N 次」唯一稳妥的办法，是提交 N 个独立 prompt。

| 开关 | 点选行为 | 点一次运行 | 每次 prompt 里的图 | 节点输出 |
| --- | --- | --- | --- | --- |
| **单图** | 点哪个换哪个，永远只保留最后点的 1 张（再点一次取消） | **1 次** | 1 张 | `[1, H, W, C]` |
| **多图** | 累加多选，缩略图上显示选中顺序编号 | **N 次**（N = 选中张数） | 1 张 | `[1, H, W, C]` |

> 早期的版本还有「逐张 N 次 / 批量 1 次」两个执行按钮，现在已经**完全移除**。「批量一次」把 N 张打包成一个 `[N,H,W,C]` 的 IMAGE 张量，工作流其实只跑 1 次，既要求下游全部支持 batch、又容易撑爆显存，和「每个图片执行一遍工作流」自相矛盾；而它和「逐张」并列还会让同一个意图出现两种入口。现在执行次数只由「单图 / 多图」决定，不再有第二个开关。

实现细节：扩展 hook 的是 `app.queuePrompt`，只在「多图 + 选中 2 张以上」时介入；每轮临时把 `selected_files` 改成单张，再串行调用 ComfyUI 原生的 `queuePrompt(…, 1, …)`。每一轮都走完整的 `graphToPrompt` → `/prompt` → job 记录 → `processingQueue` 复位流程，因此队列面板、进度、错误提示都与手动点 N 次运行一致，不会卡住。单图模式完全不拦截，就是普普通通的一次运行。

**运行提交成功后会自动清空已选图片**（`selected_files` 写回 `[]`、缩略图上的编号和选中框全部消失），不用一张张点掉；图库网格仍保留，可以直接接着点下一批。只有提交成功才清空，运行报错时选区保持不变，方便重试。手动「清空选择」按钮也还在。

常见的「文件夹批量导入」型工作流，本质大多是 `Load Image Batch` 输出 IMAGE 批次、一次跑完；少数是用外部脚本逐张提交 prompt。本节点做的是后者，所以**不需要再挂循环节点 / 子图 / 批处理节点**，也不需要 API 脚本。

## 主要功能

| 能力 | 说明 |
| --- | --- |
| 网址抓取 | 静态 HTML、SPA 内嵌 JSON、纯 JSON API、每行一个图片网址，都能提取图片；Civitai 与 PromptHero 有内置适配 |
| 加载内容 | Civitai 与 PromptHero 分别使用“加载内容1”（排序/榜单）和“加载内容2”（分类/模型），两个下拉互不影响，并各自记住上次选择 |
| 网站快捷栏 + 设置 | 默认只预置 `civitai` 和 `prompthero`。列表只存浏览器 `localStorage`，**不写进工作流 JSON** |
| 无限滚动 | 滚动到底自动加载下一页；支持 `nextPage` 游标、`{page}` / `{offset}` / `{cursor}` 分页模板；固定正方形行高。整页被去重或接口偶发空页时会自动续拉，不会卡死在底部。自动滚动到 1500 格会**暂停**，点 **「加载更多(解除上限)」** 即可无视上限继续加载，解除后滚动也不再受限 |
| PromptHero 分页 | 使用站点公开搜索接口按页加载，不再局限于首页 24 张；滚动会自动续拉 |

| 缩略图代理 | 后端代抓并缓存缩略图，解决跨域、防盗链、Referer 校验；Civitai CDN 自动改用 `width=400` 小图 |
| 单图 / 多图 | 面板顶部一键切换；单图点任意图片自动替换，多图累加并编号；同时决定运行 1 次还是 N 次，选择结果随工作流保存 |
| 运行 | 面板「▶ 运行(N 次)」与 ComfyUI 原生 Run 走同一条链路，用哪个都行；提交成功后自动清空选区 |
| 站点兜底 | Cookie / UA / Referer / HTTP 或 SOCKS5 代理、自定义正则 |
| 尺寸统一 | 等比缩放+填充、居中裁剪、直接拉伸、保持原尺寸（默认统一到 1024×1024，避免网页原图过大撑爆显存） |
| Qwen 扩图草图（推荐首选） | `ShangguQwenOutpaintDraft`：源图 + 目标比例 → 低像素 16:9 草图。内部一条链搞定：去黑边 → 灰底画布(#808080) → Qwen2.1 文本编码器看图 → outpaint LoRA 全图重绘（**不用 mask、无接缝、不多手脚**）。拿草图再去跑 MOSS 出最终图 |

## 安装

1. 把整个文件夹放到 ComfyUI 的 `custom_nodes/` 下：
   ```
   ComfyUI/custom_nodes/ComfyUI-Shanggu-WebGallery/
   ```
2. 重启 ComfyUI（或浏览器 **Ctrl+F5** 强制刷新，扩展 JS 是动态扫描的）。
3. 双击画布搜索 **网页图库选图器**（`ShangguWebImageGallery`）和 **Qwen扩图草图→IMAGE**（`ShangguQwenOutpaintDraft`，竖图转横图首选）。本插件只有这两个节点；节点若没出现，重启一次 ComfyUI 即可。

无需 `pip install`：核心依赖 `aiohttp`、`PIL`、`numpy`、`torch` 都是 ComfyUI 自带的。

**可选依赖**（不用也能跑，只是能力增强）：

- `beautifulsoup4`：装了以后 HTML 标签解析更完整；没装会自动退回正则提取。
- `aiohttp-socks`：只有要用 `socks5://` 代理时才需要；HTTP 代理走 aiohttp 原生支持。

已在 **ComfyUI 0.45.0（前端 1.59.1）** 上开发验证。

## 快速上手

1. 节点面板的网址框里填地址，默认是 `https://civitai.red/api/v1/images?limit=20`。
2. 点 **搜索**，出现缩略图网格；**向下滚动**自动加载更多。滚到 1500 格时自动滚动会暂停（防止越滚越卡），状态栏会提示，此时点面板底部的 **「加载更多(解除上限)」** 就解除限制、继续一页页往下加载；解除后按钮变成「加载更多(不限)」，滚动也不再受 1500 格约束。重新点 **搜索** 会恢复默认软上限。
3. 面板顶部选 **单图** 或 **多图**：单图点哪个换哪个，运行 1 次；多图可点选多张（再点一次取消），每张各运行 1 次。
4. 点缩略图选中，原图会自动下载到 `input/`。
5. 把 `images` 输出接到图生图工作流，点面板的 **▶ 运行** 或 ComfyUI 的 **运行** 都行。

面板三个标签页：

- **网址抓取**：常规用法。
- **导入图片**：选择本地图片文件，可多选。
- **导入文件夹**：选择整个文件夹，批量导入并全选。

插队运行（Queue Front）时会按选中顺序提交，出图顺序与点选顺序一致。

> 如果多图工作流曾出现「卡住」，通常是旧版把多张网页原图（常有 1500~3000px）一起塞进 1024 工作流，latent 暴涨、16GB 显存很容易挂起。现在多图一定拆成 N 次独立运行，且所有图统一缩放到 `target_width/height`；确实要保留原分辨率，把 `size_mode` 设为「不统一(需同尺寸)」。

## 节点与输出

### 网页图库选图器 `ShangguWebImageGallery`

| 输出 | 类型 | 说明 |
| --- | --- | --- |
| `images` | `IMAGE` | 当前这一张图的张量 `[1, H, W, C]`，等价于 LoadImage |
| `masks` | `MASK` | 对应掩码（无 alpha 时为全 0） |
| `count` | `INT` | 本次加载的图片数量（正常恒为 1） |
| `info_json` | `STRING` | 这张图的元信息 JSON：原图网址、文件名、尺寸、页面 prompt 等 |

主要输入：`site_url`、`selected_files`（由面板自动维护）、`select_mode`、`size_mode`、`target_width`、`target_height`。

- `select_mode` 是唯一的模式开关，为可选输入，旧工作流没有它也能正常加载（默认单图）。
- `multi_mode` 是早期「逐张 / 批量」留下的**隐藏占位参数**，值被完全忽略，保留它只是为了让老工作流的 `widgets_values` 顺序不错位；前端会把它隐藏，你不会在节点上看到它。
- 多图模式如果一个 prompt 里意外收到 2 张以上（说明前端扩展没加载或工作流里有第二个多图节点），节点会明确报错而不是悄悄退化成批次，按提示 **Ctrl+F5 强制刷新**即可。

### Qwen 扩图草图 `ShangguQwenOutpaintDraft`（竖图转横图首选）

**把 9:16 竖图变成 16:9 横图、人物完整不变形、左右是自然场景——一个节点直接出草图。** 内部封装了 ausboss `Qwen-Image-2.1-Outpaint-LoRA` 的官方全链路，你只接一张图 + 选目标比例即可，不用自己搭十几个节点。

接线（整个扩图阶段就这一个节点）：

```
图库选图器 / LoadImage
   └─ image → Qwen扩图草图 (Shanggu)
                ├─ draft     → SaveImage（低像素草图，长边默认 768）
                └─ reference → PreviewImage（生成后的扩图草图，与 draft 同一张）
```

然后拿 `draft` 这张 16:9 草图，去你的 **MOSS 工作流**当输入重绘成最终风格。

**它是怎么解决多手脚 / 接缝 / 黑边的**（这是之前所有方案失败的根因）：

| 之前失败的做法 | 本节点做法 |
|---|---|
| mask 扩图：只重绘扩展区 → 模型把断肢「续写」成第二只手，接缝有硬边 | **不用 mask**，Qwen outpaint LoRA 训练目标就是「灰区补全、原图区不动」，全图重绘，无矩形接缝 |
| img2img 直接重绘：调低 denoise 复刻填充条纹，调高被文字带跑 | 参考图是**纯灰 #808080** 底 + 文本编码器直接看图（outpaint LoRA 的规定输入），denoise 固定 1.0 |
| 拉伸 / 边缘延展填充 | 源图**等比缩放、整图完整保留**，左右空区填纯灰交给模型生成 |

节点内部依次做：自动去黑边 → 等比缩放贴到目标比例灰画布（32 倍数对齐）→ 加载本地 Qwen2.1 模型（`qwen_image_2.1_int8_convrot` + `qwen3vl_8b_int8_convrot` + `qwen_image_2.1_vae_bf16`）→ 加载 `画面扩展 qwen-image-2.1-outpaint-v2` LoRA → `TextEncodeQwenImage21` 编码灰底参考图 → `KSampler` 25 步 / CFG 1 / euler / simple / denoise 1 → `VAEDecode` 出图。**加载器走 ComfyUI 缓存，不会重复占显存。**

参数要点：

- `aspect`：目标比例，选 **16:9**；`draft_long_side` 草图长边默认 **768**（只是草图，够用且快）
- `prompt`：**用 Qwen3-VL 看图写场景描述**（画面里有什么、背景是什么），节点会自动在前面加官方触发句 `Outpaint the image: replace the solid gray areas...`；留空也能跑，但写了扩展区更贴合
- `quality`：`质量(25步)`（默认，官方参数）或 `快速(8步+turbo)`（叠加本地 8-step turbo LoRA，牺牲一点质量换速度）
- 模型文件名都是下拉可选，默认已选中本机确认存在的版本；如果你的文件名不同，下拉里改即可

**前置条件**：本地需有上面的 Qwen2.1 模型 + 画面扩展 outpaint LoRA（你的环境已齐全）。这一步产出的是**低像素草图**，最终的清晰度、风格由后面的 MOSS 工作流负责——两者分工，各用其所长。

## 内容过滤

高级设置中的 **「内容过滤」** 有三个模式：

- **不显示 NSFW**：只保留站点明确标记为安全的内容。
- **全显示**：安全与 NSFW 内容都保留。
- **仅有 NSFW**：只保留站点明确标记为 NSFW 的内容。

Civitai 与 PromptHero 会先向站点请求相应范围的数据，再由后端按响应中的 NSFW 标记统一过滤。旧工作流里的 `safe_only: true/false` 会自动映射为“不显示 NSFW / 全显示”。

> 自行添加的其他网站没有统一年龄分级接口，只能识别网页或 JSON 响应里明确提供的 `nsfw`、`nsfwLevel`、`browsingLevel`、`rating` 等字段；没有这些标记的图片会被视为安全内容。

## 加载内容（排序 / 分类 / 模型）

网址框下方有两个独立下拉：**「加载内容1」**选择排序/榜单，**「加载内容2」**选择分类或提供商。改变其中一个不会清除另一个；Civitai 与 PromptHero 各自记住上次选择，互不影响。

| 站点 | 加载内容1 | 加载内容2 |
| --- | --- | --- |
| civitai | 最新上传 / 周榜 / 月榜 / 年榜 / 总榜 / 最多点赞 / 最多评论 / 最多收藏 | 动物 / 动漫 / 海滩 / 卡通 / 猫 / 漫画 / 角色扮演 / 赛博朋克 / 狗 / 龙 / 精灵 / 奇幻 / 兽人 / 女仆 / 日本漫画 / 机甲 / 怪物 / 肖像 / 写实 / 机器人 / 自拍 / 蒸汽朋克 |
| prompthero | 最新作品 / 最多收藏 / 最多浏览 | 11 个作品分类，以及 GPT / ChatGPT Image、Midjourney、Stable Diffusion、DALL·E、FLUX、Ideogram、Nano Banana、Seedream、Grok Image |

Civitai 的排序使用 `sort` / `period`，第二项使用图库标签的数字 ID（`tags=<ID>`），例如动物 `111768`、卡通 `5186`、动漫 `4`。PromptHero 第一项使用 `sort=newest|favorites|views`，第二项使用 `category=<分类>` 或 `model=<提供商>`；两项可以组合，例如“最多浏览 + Midjourney”。

## 网站快捷栏与网站设置

默认快捷栏只有 **civitai** 和 **prompthero** 两个站点。面板底部 **「⚙ 网站」** 可以改名、改址或添加其他网址；列表只保存在浏览器 `localStorage`，不写进工作流 JSON。

## 站点适配 / 图片来源

### civitai.red

`https://civitai.red/images` 网页版会返回 **Cloudflare 403**，但 `https://civitai.red/api/v1/images?limit=20` 可直接返回 JSON。输入 `/images` 时会自动切换到该接口，并按两个下拉分别追加 `sort` / `period` 和数字标签 `tags`。

### prompthero.com

PromptHero 使用公开的 `prompt.search` 接口，每页 24 个作品，并根据 `pagination.hasNextPage` 继续加载；不再依赖只包含首页内容的服务端 HTML。搜索词、排序、分类和提供商都会传给接口。

每个作品在网格里只显示一张封面，点封面可展开该作品的 1920、1080、640、square 等尺寸。展开数据会缓存；ComfyUI 重启后也可以按作品的 CDN 标识重新重建尺寸列表。

> 其他需要登录或强反爬的站点，请直接填写其 JSON 接口地址，或在高级设置里配置 Cookie、UA 与代理。

抓取器能识别的来源：

- `<img>` 的 `src` / `data-src` / `srcset`、`<a href>` 指向的图片、`og:image`、CSS 背景图；
- `<script type="application/json">` 以及页面内嵌 JSON 里的图片字段；
- JSON API 响应（递归查找 url 字段）；
- 纯文本里每行一个网址；
- 自定义正则（`url_regex`）强制提取。

默认会过滤 logo / icon / avatar / placeholder / favicon 之类的非内容图，可在高级设置里关闭。

## 附带修复：DOM 面板「只占节点一半宽」

`js/sg_domwidget_width_fix.js` 是一个独立的通用前端补丁。ComfyUI 新版前端把 DOM 面板画在独立 HTML 覆盖层上，覆盖层宽度按 widget 创建时缓存的节点默认宽度计算，节点后来被拉宽或从工作流恢复尺寸时不会同步，于是面板只占一半宽——**所有带 DOM 面板的第三方节点都可能偶发**。

补丁每 250ms 巡检，只修明显卡在默认宽度的面板，不会动刻意做窄的布局。本节点自身也内置了宽度同步逻辑。

- 手动执行一次：浏览器控制台输入 `sgFixDomWidth()`
- 关闭：`localStorage.setItem('sg_domwidth_fix', 'off')` 后刷新页面

## 后端接口

节点通过 ComfyUI 的 `PromptServer` 注册以下路由（ComfyUI 0.45 会同时挂到 `/xxx` 和 `/api/xxx`）：

| 路由 | 作用 |
| --- | --- |
| `GET /sg_gallery/health` | 健康检查 |
| `POST /sg_gallery/fetch` | 抓取一页（带会话去重、游标分页、自动改写、榜单排序） |
| `POST /sg_gallery/parse` | 解析粘贴的 HTML / JSON / 网址列表 |
| `POST /sg_gallery/expand` | 点开检索页封面时取回该作品的同系列图片 |
| `GET /sg_gallery/thumb` | 缩略图代理 + 磁盘缓存 |
| `POST /sg_gallery/select` | 下载选中原图到 `input/` 并返回文件名与尺寸；同 URL 只下载一次 |

> 源码文件统一用 `sg_` 前缀命名（`sg_nodes.py` / `sg_qwen_outpaint.py` / `sg_server.py` / `sg_scraper.py` / `sg_adapters.py`），避免自定义节点目录进入 `sys.path` 后遮蔽 ComfyUI 内建的 `nodes` / `server` 模块。

## 已知限制

- 纯浏览器渲染、且需要登录/有强反爬的站点，后端直接抓可能拿不到图；Civitai 与 PromptHero 已有专用适配，其他站点请直接填 JSON 接口地址。
- 多图模式总耗时约为单张 × N，队列里会依次出现 N 个任务，属正常现象；一个工作流里请只放一个处于「多图」模式的选图器节点。
- 自动滚动到 1500 格会暂停；点「加载更多」解除上限后可继续，直到 20000 格的浏览器安全兜底值（正常浏览到不了）。后端只在站点连续 3 次返回空页时判定到底。写进工作流的条目最多保存 3000 条，超过部分重新搜索即可；ComfyUI 重启后后端内存中的分页游标会清空，需再点一次「搜索」重新续拉。
- 抓取与缩略图缓存写在节点目录下的 `.cache/`，已加入 `.gitignore`；缓存的是第三方站点图片，请勿随仓库再分发。
- 请遵守目标站点的服务条款与图片版权，本节点只提供技术能力。
